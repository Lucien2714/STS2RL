# Step 2-p（修复）：PPO 更新时保留正在打战斗的决策

*2026-10-06*

## 问题

这个问题由 Codex 在审查 PBRS 设计时发现，存在于之前所有使用 `--search-fights-out-of-rollout` 的训练中（Step 2-e、2-h、2-i、2-j、2-k、2-n）。

战斗由 MCTS 打，战斗步不进 rollout：每个战斗步的奖励由 `_fold()` 加到这个 lane 最后一条宏观记录上，死亡会把这条记录标为终局。

`observe()` 在 rollout 满 256 条时立刻调用 `update()`，`update()` 训练后清空**所有** lane 的记录。这时其他 lane 大多正在打战斗。对这些 lane：

1. 进入战斗的决策在战斗结束前就被训练，没有得到这场战斗的楼层奖励、boss 奖励和终局。
2. 清空后，`_fold()` 找不到上一条记录，战斗剩余的奖励进入 `carried_reward`，记到这个 lane 的**下一个**决策上。
3. 如果 agent 在这场战斗中死亡，`_fold()` 把奖励清零，死亡没有记录为任何决策的终局。

**影响（估算，没有实测）：** step2n 中 2/3 的环境步是战斗步，每局约 10.9 场战斗，每次更新约 32 场。每次更新时约有 4–5 个 lane 正在打战斗，所以约 14% 的战斗跨越了一次更新。600 局中约 800–1000 个进入战斗的决策受影响，约 14% 的死亡没有记为终局。boss 战较长，boss 奖励和 boss 战死亡受影响的比例可能更高。

## 修复（`src/sts2rl/agents/ppo.py`）

- **新参数 `hold_open_steps`：** `cli.py` 在“战斗用搜索且不进 rollout”时打开它；第一次 `choose_external(record=False)` 也会打开它。
- **`_holds_open_step(lane)`：** 打开时，lane 的最后一条记录在两种情况下才算完成：这一局结束（`done` 或 `episode_end`），或者已经观察到下一条记录。待定决策不算完成，因为它可能被 `discard_decision` 撤销，之后仍可能进入战斗。
- **`update()`：** 每个 lane 只训练已完成的前缀，被保留的最后一条留到下一次更新。前缀最后一步用被保留记录的采样价值（`old_value`，奖励单位）做 bootstrap，trace 在这里截断。只删除训练过的前缀。新指标 `held_steps`。`rollout_steps` 由 `update()` 自己写入，KL 在第一个 minibatch 就停止时也有这个值。
- **`_update_if_ready()`：** 自动更新在同一次持锁中复查“已完成的记录 ≥ 256”，只有真的更新了才调用 `on_update`（保存 checkpoint）。`observe()`、`reset()`、`finish_episode()` 都通过它触发更新：截断或重置会关闭被保留的记录，也可能让 rollout 达到阈值。
- **不打开时：** 结果与修改前相同（测试比较了两种开关下的优势、回报、指标和权重）。

**限制：** checkpoint 只保存模型、优化器和回报缩放，不保存 rollout。重启后，被保留的记录和其余未训练的记录一样会丢失。

## 审查

- Codex 第一次审查：小改后提交。
  1. 待定决策可被撤销，不能作为“已完成”的条件；
  2. 自动更新的阈值检查与执行之间有竞态（修改前就存在）；
  3. 截断释放被保留的记录后不检查阈值；
  4. KL 在第一个 minibatch 停止时缺少 `rollout_steps`（修改前就存在）。
- 4 项都已修改，并各有回归测试。
- Codex 确认：`tail_value` 的值和单位正确，不受 `_ReturnScale` 变化影响；奖励不会重复计入；优势归一化、minibatch 和 KL 提前停止没有索引错位；checkpoint 的保存和恢复没有问题。

## 测试

`tests/test_ppo_agent.py` 新增 20 个测试，修改 2 个，覆盖：战斗剩余奖励记到被保留的记录；更新后的死亡标记终局；其他 lane 不受影响；下一次更新训练被保留的记录；撤销决策后再进入战斗；两个 lane 同时判定已满只更新一次；数量降到阈值以下时跳过；截断和重置后达到阈值时更新；被保留的记录跨多次更新、跨回报缩放变化；`initialize_from()` 拒绝有被保留记录的 agent；`update()` 确实传入 `tail_value`。

全部 756 个测试通过（修改前 735 个），ruff 无问题。
