# Step 1-b：拟合叶子评估

*2026-10-03*

## 做了什么

按计划"权重怎么来"的 1–5 步：手设权重 → 用 MCTS（50 次模拟、两回合深度）打 119 个训练快照 × 3 个世界 → 逻辑回归拟合 → 用新权重再打一轮、再拟合 → 在 24 个 holdout 快照上检查。

- **`scripts/fit_leaf_evaluator.py`**：读 `boss_mcts_eval.py --record-features` 的结果，每个搜索过的决策点是一行（特征 + 这场最后的输赢），按场加权（每场的行权重合计为 1，长的战斗不会因为行数多而占更大比重），拟合并报告 AUC（第一个决策点、全部决策点）和校准表；`--check` 的数据只用来打分、不参与拟合。
- **`boss_mcts_eval.py`** 记录特征的同时，把每个决策点的原始状态存进 `<out>.states.jsonl.gz`；拟合脚本有这个文件时从状态重新计算特征，所以改了特征不用重打。
- **`fit_weights`**：改用 numpy（只在拟合时导入，评估本身仍然不依赖它），支持按样本加权、L2（偏置项不惩罚），以及**符号约束**（见下面"检查发现的问题" 4）。

## 检查发现的问题

逐步看了一场 boss 战的搜索过程（每个决策点各候选的访问次数和价值），发现前两个问题；用部分数据试拟合发现第三个；拟合结果发现第四个。

1. **局面看起来输定时，搜索等于随机。** 所有叶子都是 0 分，各候选的价值没有区别。→ 输局按已经造成的伤害给一点分：`LOSS_PROGRESS_WEIGHT`（0.1）×（1 − 敌人剩余 HP 比例），永远低于任何胜局（≥ 0.7）；战斗中的局面是 p × 赢的价值 +（1 − p）× 输的价值。输掉的那一步是 `game_over`，看不到敌人，所以搜索把最后一个战斗中的状态一起交给评估函数。"看起来输定"只是评估函数的估计，这时候打得仔细最重要。
2. **50 次模拟下访问几乎平均分配。** 兄弟节点的价值只差 0.01–0.02，被探索项（0.7）盖过。→ UCB 里的 Q 按这棵树见过的最小、最大值归一化（MuZero 的做法）。同一个小例子（价值差 0.001）里，最好的动作的访问比例从 36% 升到 58%；同一场 boss 战的最后一个决策，最好的候选拿到约 50 次里的 41 次。
3. **开局特征预测不了输赢**（第一个决策点 AUC ≈ 0.5）。开局时 HP、敌人 HP 比例对每个快照几乎一样，决定胜负的是牌组，而原来的特征看不到牌组。计划的特征表里有"竞速"和"敌人撑几回合"，Step 1-a 没有实现。→ 新增三个特征：
   - `deck_damage` / `deck_block`：从手牌、抽牌堆、弃牌堆的卡牌描述里读出每点能量的伤害和格挡（"Deal 5 damage twice"、"X times"、"to a random enemy 3 times" 都能读；X 费用按一回合的能量算；不可打出的牌按 1 点能量、0 收益算），乘以每回合能量；
   - `race`：log(玩家能撑几回合) − log(敌人能撑几回合)，玩家 = 有效 HP / 来袭伤害，敌人 = 敌人总 HP / 牌组每回合伤害（敌人易伤时 ×1.5），都截断在 20 回合。
   - 只读打出时的效果，"每当……"类触发和随状态变化的伤害读不到，有的牌组会被低估。只支持英文描述（模拟器和 mod 都是英文）。
4. **自由拟合有几个权重的符号是反的**：`enemy_vulnerable` −0.64、`enemy_growth` +0.98、`survival_margin` −1.02。逻辑回归学到的是相关性：长的战斗给了敌人时间叠力量，而长的战斗也正是玩家活下来的战斗。搜索用这个分数比较动作，反的权重就是反的激励——它会避免给敌人上易伤。→ `FEATURE_SIGNS` 规定每个特征在"其他都不变"时影响胜率的方向，`fit_weights` 用投影梯度下降把权重限制在对应的一侧（默认开启，`--free` 关闭）。holdout 上的预测几乎不变（全部决策点 AUC 0.909 → 0.887，第一个决策点 0.845 → 0.855），被压到 0 的是 `enemy_vulnerable`、`enemy_growth`、`survival_margin` 等；易伤仍然通过"两回合后敌人 HP 更低"间接起作用。

另外：第一次运行用的是修复前的搜索、没有新特征，打了 77 场后停掉，数据移到 `runs/boss-mcts/superseded/`，不参与拟合。

## 结果

数据都在 `runs/boss-mcts/`。每轮 357 场（119 个训练快照 × 3 个世界），世界种子和搜索种子在各轮之间相同，所以每场在另一轮里都有配对的一场，各轮之间唯一的区别是权重。

**第一轮（手设权重）**：赢 59 场（16.5%）。平均每个决策 1.9 秒（7 个模拟器同时跑），每场约 31 步、45 秒。赢的时候平均剩 29% HP；输的时候 boss 平均剩 31% HP。

按 boss：

| boss | 场数 | 赢 |
|---|---|---|
| Lagavulin Matriarch | 60 | 23.3% |
| Soul Fysh | 72 | 22.2% |
| Vantom | 36 | 22.2% |
| Kin Priest + Kin Follower | 72 | 18.1% |
| Ceremonial Beast | 66 | 10.6% |
| Waterfall Giant | 51 | 2.0% |

119 个快照里，80 个在 3 个世界里一场都没赢，24 个赢 1 场，10 个赢 2 场，5 个全赢。

**拟合**：L2 从 1e-2 改为 1e-3。1e-2 时高分段明显低估（预测 0.68，实际 0.95）；1e-3 和 1e-4 的校准都接近对角线，选 1e-3 是因为 18 个特征对 357 场有过拟合的风险。

**第二轮（第一轮拟合的权重，`weights_round1.json`）**：

| | 第一轮（手设） | 第二轮（拟合） |
|---|---|---|
| 赢 | 59 / 357（16.5%） | 73 / 357（20.4%） |

配对：36 场从输变赢，22 场从赢变输，双侧符号检验 p = 0.087。

用第一轮的权重给第二轮的数据打分（这些数据没有参与拟合）：

| | 拟合权重 | 手设权重 |
|---|---|---|
| AUC，全部决策点 | 0.803 | 0.684 |
| AUC，第一个决策点 | 0.667 | 0.628 |
| 预测 0.60–1.00 → 实际 | 0.75 → 0.82 | 0.84 → 0.34 |

手设权重严重高估，拟合后基本校准。

**holdout（两轮一起拟合的权重 `weights_round2.json`，24 个快照 × 3 个世界 = 72 场，从未参与拟合）**：MCTS-50 赢 16 场（22.2%）。

| | 拟合权重 | 手设权重 |
|---|---|---|
| AUC，全部决策点 | 0.909 | 0.812 |
| AUC，第一个决策点 | 0.852 | 0.820 |
| 预测 0.60–1.00 → 实际 | 0.73 → 0.92 | 0.85 → 0.46 |

高分段略微低估，但那一档只有约 5 场。

**自由拟合与符号约束拟合的对比**：两组权重都用第一、二轮的 714 场拟合，各打一遍同样的 357 场训练战斗（配对）。

| 权重 | 赢 | 赢时剩余 HP | 输时 boss 剩余 HP |
|---|---|---|---|
| 符号约束 `weights_signed.json` | 89 / 357（24.9%） | 28.8% | 29.8% |
| 自由拟合 `weights_round2.json` | 84 / 357（23.5%） | 26.4% | 30.6% |

配对：只有符号约束赢的 22 场，只有自由拟合赢的 17 场，p = 0.52，两者在噪声范围内相同。**选符号约束的权重**：胜率不低，而且没有反向的激励。它对比手设权重：89 对 59，只有它赢的 45 场、只有手设赢的 15 场，p < 0.001。

各轮胜率汇总（同样的 357 场）：手设 16.5% → 第一轮拟合 20.4% → 两轮拟合（符号约束）24.9%。

最终权重复制到 `src/sts2rl/search/weights/act1_boss_step1b.json`（`runs/` 不进 git），Step 1-c、1-d 都用它：

| 特征 | 权重 | 特征 | 权重 |
|---|---|---|---|
| bias | −2.58 | player_strength | +0.94 |
| hp_ratio | +3.32 | player_dexterity | +0.10 |
| lethal_incoming | −0.56 | player_buffs | +0.54 |
| race | +0.45 | potions | +0.86 |
| deck_damage | +2.36 | enemy_hp_ratio | −3.09 |

其余（survival_margin、deck_block、enemy_block_ratio、enemy_growth、enemy_vulnerable、enemy_weak、player_debuffs、status_cards）被约束压到 0。
